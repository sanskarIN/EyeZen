# EyeZen v1.2.1 — Release quality gates (development plan)

**Status:** Automated checks completed; maintainer authorized publication on 2026-10-25 while independent hardware, accessibility and certain security follow-ups remain **unchecked** in [issue #18](https://github.com/sanskarIN/EyeZen/issues/18) and [issue #29](https://github.com/sanskarIN/EyeZen/issues/29). This is a documented exception to the previous manual acceptance prerequisite, **not a pass for any unperformed test**. **Baseline until tag publication:** v1.2.0.
**Scope:** Stability, evidence, accessibility, permission predictability and truthful release communications. No physical brightness/HDR/ICC claims.

## Gate 1 — CI and source review (must pass)

- [ ] Frontend `npm ci`, `npm run lint`, `npm run typecheck`, `npm run test` and `npm run build`.
- [ ] Rust `cargo fmt --all -- --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked`.
- [ ] Windows x64 MSI, macOS Apple Silicon DMG, Linux amd64 DEB/RPM build in clean CI.
- [ ] Download and test unsigned release-candidate installers from the [preview CI artifacts](preview-installers.md) before stable publication.
- [ ] Tests cover schedule boundary conditions, corrupt settings recovery (restore a valid prior configuration before using defaults, and preserve invalid originals), denied notification permissions and rejecting oversized native settings before replacing a valid file.
- [ ] Security/dependency review: document advisories affecting distributed app before tagging.
- [ ] Version, lockfiles, changelog, release notes and installer metadata must agree on v1.2.1.
- [ ] Release publishing verifies exactly one Windows MSI, macOS DMG, Linux DEB and RPM; downloaded release files pass `sha256sum -c SHA256SUMS.txt`. Do not confuse uploaded CI artifacts with tested installations.

## Gate 2 — Real desktop acceptance (record evidence, do not infer from CI)

Record date, OS/version, session type, display count, scaling, screenshot/video where useful, action, actual outcome and tester initials.

- [ ] Windows: overlay appears on every detected monitor with common and mixed DPI scaling; no clicking/typing interception.
- [ ] Windows: disconnect/reconnect displays, negative coordinates, resolution changes, sleep/wake, emergency tray disable.
- [ ] macOS: verify stand-alone DMG startup, overlay transparency, click-through, closing window and focus transitions.
- [ ] Linux X11: verify supported/experimental window-manager behavior; failures remove overlays and report correctly.
- [ ] Linux Wayland: no attempt at unsupported global overlay, honest capability status.
- [ ] All: no lingering tint after disable, emergency action, quit, app crash/restart where OS permits cleanup.
- [ ] All: ensure color-sensitive workflows can disable overlays immediately.
- [ ] All: verify persisted settings, malformed JSON recovery, permission-denied notifications and shortcut conflicts.

## Gate 3 — Web and accessibility acceptance

- [ ] Deploy a test build without breaking live v1.2.0 until branch is reviewed.
- [ ] Verify `/EyeZen/` and `/EyeZen/docs/` paths plus asset loading after deployment.
- [ ] Chrome, Firefox and Safari: validate persistence, safe import/export, no unsolicited permission prompts, reload behavior.
- [ ] Keyboard-only navigation, visible focus, sufficient contrast, zoom to 200%, reduced motion and mobile viewport.
- [ ] Browser unsupported-display explanations remain explicit.

## Release safeguards

1. Merge independently reviewed PRs only after their checks pass.
2. Before tagging, update `package.json`, `package-lock.json`, `src-tauri/Cargo.toml`, `Cargo.lock` and `tauri.conf.json` to a consistent v1.2.1, along with release automation and notes.
3. Ensure no automatic release runs from documentation changes or unrelated pushes.
4. Publish hashes with every installer. Describe unsigned binaries and any OS warnings accurately.
5. Tag stable only after release-critical manual tests are recorded; otherwise continue using development or pre-release builds.

## Known limitations, not blockers to honest disclosure

The app uses visible screen-tint windows, not monitor hardware brightness or calibrated color management. Linux Wayland global overlay is unsupported. Browser reminders run only while the tab is active and may be delayed by OS suspension. Successful packaging cannot validate every real device.
